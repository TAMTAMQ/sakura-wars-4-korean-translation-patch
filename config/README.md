# 채택 입력과 경계

`image-expansions.json`은 기존 ADCG 저장 범위를 넘어서는 이미지 수정의 추가 타일을 명시한다. 현재 CG_ALL1.DAT b736(검수표 #53)에만 적용한다. 원래 압축 해제 크기 98,520바이트, 표·픽셀 풀 경계, 타일 좌표·중복을 확인한 뒤 (128,128) 한 타일을 추가하며 전체 캔버스는 유지한다. 압축 헤더의 해제 크기를 갱신하고 PRS 왕복·최종 이미지 전체 픽셀 일치를 검증한다. 등록되지 않은 해제 크기 변화는 재삽입기가 거부한다.

`baseline.json`은 DCP SHA-256, 템플릿 커밋, 232개 기준 파일의 크기·SHA-256과 구 자료 비교 해시를 소유한다. 주 빌드는 매번 기준 파일 크기와 해시를 확인한다.

`text-bindings.json`은 복원한 문자열의 ID, 위치, 원본 raw byte, 가용 길이와 현재 문안 기준선을 소유한다. 정상 문안 편집에서는 수정하지 않는다. 새로운 경계 채택은 근거를 남기고 별도로 갱신한다. BIN 텍스트 경계는 기존 스캐너의 후보이므로 전체 모집단이 확정된 것으로 간주하지 않는다.

`encoding.json`은 글자→개선판 코드다. 기존 한글은 구 코드의 첫 바이트에 0x68을 더한 F0~F7 영역으로 옮겨졌으며, 첫 바이트의 0x08 비트는 그 글자 뒤 공백이다. 예: `사쿠라 군` = `f0a6 f0a7 f8a8 f0a9`. 이는 반복된 대사·레이블의 원문과 일치한다. 추가 타일 `f7ca~f7d1`은 `쭉 눴 엠 훙 멧 섞 뤼 …`다. `f7d1`은 공백이 아닌 말줄임표다. 타일 근거는 `research/unknown-glyphs.png`.

빌드는 무편집 항목을 재인코딩하지 않는다. 동일한 표시가 여러 원시 코드로 존재하므로 raw byte를 보존하는 것이 기준이다. 편집 시 등록 한글과 CP932 문자를 인코딩하고 기존 용량 안에서 NUL 패딩한다. 해당 슬롯 밖의 쓰기는 허용하지 않는다.

실행 파일은 기준선 그대로 소비한다. 데이터 슬롯 편집으로 실행 명령을 생성·이동하지 않으며, 원래 반각 구현의 어셈블리 원천은 아직 없다. 새로운 기계어 변경에는 별도 ISA 명세와 검산이 필요하다.

현재 적용 범위는 지정 DCP 하나다. 다른 수정본이나 폰트가 들어오면 해시·경계·인코딩 명세를 재검토한다.

공유 문안의 권위본은 assets/translation/units/, 사용처는 segments/의 unit/form 참조다. text-bindings.json은 이관 과정에서 바꾸지 않았다. 빌드는 전체 출현 ID와 등록 경계를 대조하고 모든 권위본·위치 파일의 실제 해시를 build-report.json의 segment_hashes에 기록한다. 자세한 편집 방식은 docs/dialogue-management.md를 따른다.


`ending-credits-layout.json`은 S0410.SBX의 스태프 이름 77개 행을 고정 두 열로 배치한다. 번역 권위본은 units 그대로이며, 이 설정에는 사용처 ID·둘째 이름 경계가 명시되어야 하는 두 행의 위치·재사용 슬롯만 둔다. 첫 이름의 한글 10칸과 반각 공백 하나를 기준으로 정렬한다. ASCR의 모든 라이브 포인터 및 기존 번역 예약 구간과 재사용 공간을 대조하며, 원본 파일 해시가 다르거나 글자가 슬롯을 넘거나 보호 구간을 침범하면 중단한다. 파일 크기와 바이트코드는 바꾸지 않는다. 투명 칸에 쓰는 U+2063 타일은 네 종류 최종 글꼴에서 모두 빈 픽셀이어야 한다.
