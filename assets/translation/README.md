# 번역 자산 구성

## 이 프로젝트의 편집 위치

현재 문안 권위본은 `units/`다. `segments/`는 적용 위치·원본 byte·용량·`unit`/`form` 참조만 보관하며 파일별 `text` 사본을 두지 않는다. `python src/dialogue.py find '대사'`로 찾고 `units/`를 편집한 뒤 빌드한다. 빌드가 권위본을 직접 읽어 모든 사용처에 반영한다. 같은 대사의 사용처마다 별도 번역 파일을 수정하지 않는다.

말투·배치가 다른 기존 번역은 같은 대사의 명시적 변형으로 보존했다. 대표 문안이 바뀐 뒤 확인되지 않은 변형을 유지하면 빌드가 중단된다. 구절을 인용하는 퀴즈 등은 `parts`/`ref`로 같은 구절을 참조한다. 자세한 구조·명령·미해결 번역 차이는 [공유 대사 편집](../../docs/dialogue-management.md)을 참고한다.

번역 입력은 문맥을 함께 이해하고 독립적으로 변경·검토할 수 있는 의미 단위로 관리한다. 색인과 `segments/`는 이를 위한 기본 구조이며, 직렬화 형식과 필드명은 프로젝트가 정한다.

## 입력과 범위

색인은 지원 원본, 선언 범위, 모집단 근거와 조사 완료 여부, 사용할 조각의 경로·순서, 단위별 검토 상태와 릴리스 승인을 식별한다. 빌드는 명시적으로 선택한 조각만 읽고 실제 사용한 색인과 조각을 각각 식별한다.

빌드는 전체 조각에서 안정 ID의 유일성, 보호 원문·raw byte, 제어 토큰과 참조의 유효성을 검사한다. 누락 검사는 지원 원본의 재현 가능한 추출이나 검토된 대상 명세에서 얻은 ID 모집단과 대조한다. 미번역 단위도 ID와 원문 유지 상태를 보존한다.

조사 중인 범위는 미확정으로 표시한다. 릴리스 전에는 선언한 범위의 모집단이 완전하다는 근거를 갖춘다. 범위는 메뉴나 본편 대사처럼 사람이 채택한 대상에 한정할 수 있다.

## 개발과 검토

각 안정 ID는 미번역·작업 중·교차 검토 필요·사람 판단 필요·완료를 구분할 수 있는 상태를 갖는다. 이름과 세분화는 프로젝트가 정한다. 번역 완성 상태와 빌드에 사용할 원문·번역 선택은 별도로 관리한다.

미완료 단위는 기본적으로 원문을 유지하며 기술 변경을 개발 빌드에 통합한다. 목적·범위·기준선을 밝힌 비배포 개발 정책에서는 명시적으로 선택한 초안을 기술 실험에 사용할 수 있다. 이 선택은 검토나 배포 승인을 뜻하지 않는다.

단위별 문안·배치·표시 승인은 내용과 근거 기준선에 연결한다. 원문·용어·제어코드·글리프 공급·배치가 바뀌면 영향받은 승인만 다시 검토한다. 기술 조건이 불안정한 부분의 표시 검토를 미루더라도 근거가 안정된 의미·용어·말투 검토는 진행한다.

표시 실패는 확인한 설계·구현 충돌로 기록하고, 채택한 사람 결정 안에서 관련 설계·문안·범위 선택지를 비교한다.

## 릴리스 승인

선언한 번역 범위의 사람 검수를 릴리스 후보 전에 마친다. 릴리스 승인은 단위별 완료 상태와 별개로, 사람이 정확한 색인과 모든 사용 조각의 내용 해시에 부여한다. 번역·보호 정보·ID 모집단·조사 완료 여부가 바뀌면 해당 릴리스 승인은 무효가 되어 다시 받아야 한다. 영향받지 않은 단위별 승인은 유지한다.
